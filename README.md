## 📌 프로젝트 개요

PublicInsight는 여러 기관에 분산된 정책 데이터를 하나로 통합하고, 정책 사이의 관계를 지식 그래프로 연결하여 사용자가 정책을 탐색하고 이해할 수 있도록 돕는 플랫폼입니다.

기존 정책 서비스는 키워드 검색을 중심으로 동작합니다. 따라서 사용자가 특정 정책은 찾을 수 있지만, 해당 정책과 관련된 다른 정책이나 지원 대상, 신청 조건 등의 맥락을 함께 파악하기는 어렵습니다.

PublicInsight는 이러한 한계를 해결하기 위해 Knowledge Graph, NLP, 추천 시스템을 결합한 구조로 설계했습니다.

사용자는 정책을 검색하는 데서 끝나는 것이 아니라, 그래프를 따라가며 관련 정책과 숨겨진 관계를 함께 탐색할 수 있습니다.

## 🚨 문제 정의

기존 정책 정보 서비스에는 다음과 같은 문제가 있었습니다.

- 정책 데이터가 여러 기관에 분산되어 있음
- 기관마다 데이터 형식과 제공 방식이 다름
- 키워드가 정확히 일치해야 원하는 정책을 찾기 쉬움
- 정책 간 관계와 전체적인 맥락을 파악하기 어려움
- 긴 정책 문서를 직접 읽어야 하므로 정보 접근 비용이 큼
- 사용자 관심사에 맞는 개인화 추천 기능이 부족함

---

## 💡 해결 전략

문제를 해결하기 위해 다음과 같은 전략을 적용했습니다.

- 여러 기관의 정책 데이터를 수집하고 공통 형식으로 정제
- Neo4j를 활용한 정책 지식 그래프 구축
- 정책, 대상, 조건, 기관 등의 관계 연결
- Elasticsearch를 활용한 정책 전문 검색 시스템 구축
- Node2Vec 임베딩을 활용한 정책 간 유사도 계산
- KoBART를 활용한 긴 정책 문서 요약
- 사용자 행동 로그를 기반으로 한 개인화 추천
- 인터랙티브 그래프 UI를 통한 탐색 경험 제공

## 🔄 데이터 파이프라인

PublicInsight는 여러 기관에서 수집한 정책 데이터를 전처리한 뒤 지식 그래프로 변환하고, 이를 검색과 추천 기능에 활용하는 구조로 설계했습니다.

### 1. 데이터 수집

- 여러 기관에서 제공하는 정책 데이터 수집
- 정형 데이터와 비정형 문서 수집
- 크롤링 및 ETL 파이프라인을 통한 데이터 통합

### 2. 전처리 및 NLP 처리

- 불필요한 문자와 중복 데이터 제거
- 정책 문서의 텍스트 정제
- Kiwi를 활용한 한국어 형태소 분석
- TF-IDF 기반 핵심 키워드 추출
- KoBART 기반 정책 문서 요약

### 3. 지식 그래프 생성

- 정책, 기관, 지원 대상, 조건 등의 노드 생성
- 정책 데이터에서 관계 정보 추출
- Neo4j를 활용한 그래프 구조 저장
- 정책 사이의 연결 관계 구성

### 4. 그래프 임베딩

- Node2Vec을 활용한 그래프 노드 벡터화
- 그래프의 구조적 특징을 임베딩에 반영
- 정책 벡터 사이의 유사도 계산

### 5. 추천 시스템

- 현재 정책과 유사한 정책 추천
- 사용자가 조회하거나 북마크한 정책을 Seed 노드로 활용
- 사용자 행동에 따른 개인화 추천 결과 생성

### 6. 서비스 제공

- FastAPI를 통한 검색·추천·사용자 API 제공
- Elasticsearch를 통한 정책 전문 검색
- Next.js 기반 인터랙티브 그래프 UI 제공
- Docker와 Nginx를 활용한 서비스 배포

## ⚙️ 주요 기능

### 1. 지식 그래프 기반 탐색

- 정책 간 관계를 그래프 형태로 시각화
- 특정 정책 노드를 선택하면 관련 정책을 확장하여 표시
- 정책, 기관, 지원 대상 등의 관계 탐색
- 마인드맵 형태의 인터랙티브 UI 제공

사용자는 하나의 정책을 검색한 뒤 관련 노드를 따라가며 기존 키워드 검색만으로는 찾기 어려운 정책까지 탐색할 수 있습니다.

### 2. 그래프 기반 추천 시스템

- Node2Vec을 활용한 정책 노드 임베딩
- 그래프 구조상 가까운 정책 탐색
- 벡터 유사도를 기반으로 관련 정책 추천
- 직접 연결되지 않은 정책 사이의 숨겨진 관계 탐색

정책의 단순한 키워드 일치 여부가 아니라, 그래프 안에서의 위치와 관계를 기반으로 유사한 정책을 추천합니다.

### 3. AI 기반 문서 요약

- KoBART 모델을 활용한 한국어 정책 문서 요약
- 긴 정책 내용을 핵심 정보 중심으로 압축
- 정책의 주요 지원 내용과 조건을 빠르게 파악할 수 있도록 구성

사용자가 긴 원문을 모두 읽기 전에 정책의 핵심 내용을 확인할 수 있어 정보 접근 시간을 줄였습니다.

### 4. 사용자 행동 기반 추천

- 사용자의 검색 기록 수집
- 정책 조회 및 클릭 기록 수집
- 북마크 기록을 사용자 관심 정보로 활용
- 관심 정책을 Seed 노드로 사용하여 개인화 추천 수행

사용자가 서비스를 이용할수록 행동 데이터가 축적되고, 이를 기반으로 관심사에 가까운 정책을 추천할 수 있도록 구성했습니다.

### 5. Elasticsearch 기반 정책 검색

- 정책명과 정책 본문을 대상으로 한 전문 검색
- Nori 분석기를 활용한 한국어 형태소 분석
- 사용자 정의 사전, 동의어 및 불용어 적용
- 정책 검색 결과의 정확도 개선
- 검색 로그 수집 및 분석

### 6. 사용자 및 관리자 기능

- 회원가입 및 로그인
- JWT 기반 인증
- 사용자 북마크 및 정책 평가
- 사용자별 추천 결과 제공
- 정책 및 사용자 관리를 위한 관리자 기능

## 🤝 Git 협업 및 코드 품질 관리

2인 팀에서도 코드 충돌과 검증되지 않은 변경을 방지하기 위해 단순화한 Git Flow 전략을 적용했습니다.

기능 개발, 코드 리뷰, 통합 테스트, 배포 준비 단계를 브랜치로 분리하고 Pull Request를 통해서만 주요 브랜치가 변경되도록 구성했습니다.

### 브랜치 전략

#### `main`

- 배포 가능한 안정적인 코드 관리
- 프로덕션 배포를 위한 최종 코드 저장
- 직접 수정하지 않고 Pull Request를 통해서만 변경

#### `develop`

- 새로운 기능을 통합하는 기본 개발 브랜치
- 기능 개발 결과를 병합하여 통합 테스트 수행
- 테스트가 완료된 변경 사항을 `main` 브랜치로 병합

#### `feature`

- 기능 단위로 생성하는 개발 브랜치
- `develop` 브랜치에서 분기하여 작업
- 기능 개발이 끝나면 Pull Request를 통해 `develop`에 병합
- 작업자와 기능을 구분할 수 있는 이름 사용
- 예: `su-feature-login`

### 협업 과정

1. `develop` 브랜치를 최신 상태로 갱신
2. 개발할 기능에 맞는 `feature` 브랜치 생성
3. 기능 개발 및 로컬 테스트 진행
4. 변경 내용을 커밋하고 원격 저장소에 푸시
5. `feature → develop` Pull Request 생성
6. 팀원 코드 리뷰 및 승인
7. `develop` 브랜치에 병합
8. `develop` 브랜치에서 통합 테스트 진행
9. `develop → main` Pull Request 생성
10. 최종 검토와 승인 후 `main` 브랜치에 병합

### 브랜치 보호 정책

`main`과 `develop` 브랜치에는 Branch Protection Rule을 적용했습니다.

- 주요 브랜치 직접 수정 제한
- Pull Request를 통한 변경만 허용
- 최소 1명 이상의 코드 리뷰 승인 필요
- 빌드 및 테스트 상태 검사 통과 후 병합
- 최신 브랜치 상태에서만 병합 허용
- 브랜치 보호 규칙 우회 방지

이 과정을 통해 한 명이 작성한 코드를 다른 팀원이 검토한 뒤 병합하도록 만들었습니다. 또한 검증되지 않은 코드가 바로 배포 브랜치에 반영되는 것을 방지했습니다.

- **MySQL**
  - 사용자, 정책, 기관, 북마크 및 평가 데이터 저장
  - 서비스 운영에 필요한 관계형 데이터 관리

- **Neo4j**
  - 정책, 기관, 지원 대상 등의 관계 저장
  - 정책 간 관계 탐색을 위한 지식 그래프 구성

### Search & Cache

- **Elasticsearch**
  - 정책 데이터 전문 검색
  - Nori 기반 한국어 형태소 분석
  - 검색 로그 저장 및 분석

- **Redis**
  - 인증 관련 데이터 관리
  - 반복 조회 데이터 캐싱을 통한 응답 속도 개선

### AI / ML

- **Node2Vec**
  - 그래프의 노드를 벡터로 변환
  - 정책 간 구조적 유사도 계산

- **KoBART**
  - 한국어 정책 문서 요약

- **Scikit-learn**
  - TF-IDF 기반 핵심 키워드 추출

- **Kiwi**
  - 한국어 형태소 분석 및 텍스트 전처리

### Infrastructure & Monitoring

- **Docker**
  - 서비스를 컨테이너 단위로 분리
  - 일관된 개발 및 배포 환경 구성

- **Docker Compose**
  - 여러 서비스의 실행 환경과 네트워크 통합 관리

- **Nginx**
  - 리버스 프록시 구성
  - HTTPS 연결 처리
  - 정적 파일 서빙

- **Grafana**
  - 서버 및 서비스 메트릭 시각화

- **Kibana**
  - 애플리케이션 로그 검색 및 분석

### Collaboration & Version Control

- **Git / GitHub**
  - 소스 코드 버전 관리
  - 기능별 브랜치 운영

- **GitHub Pull Request**
  - 코드 리뷰 및 승인 기반 병합 절차 운영

- **GitHub Branch Protection**
  - `main` 및 `develop` 브랜치 직접 변경 방지
  - 승인 및 상태 검사 기반 병합

- **GitHub Actions**
  - Pull Request 빌드 및 테스트 상태 검사 자동화
